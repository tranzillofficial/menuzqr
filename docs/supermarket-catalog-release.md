# Supermarket catalog release, 2026-10-17

Follow-up: the owner confirmed all uploaded ImageKit images were reviewed before upload. All 21,342 source image associations now have approved rights; images for the 19,152 available products are visible through authenticated RLS. Product identity review remains pending for 2,190 rows independently of image rights. Pagination is 10 products per page.

New-product entry starts with the optional barcode. Scanning/entering it finds approved shared source records, fills a unique match, and asks the manager to select when several packs match. Unknown codes keep manual entry available. Name suggestions normalize Arabic spelling, digits and word order and rank fuzzy matches; the manager chooses the matching pack explicitly. Applying source details retains the entered physical barcode and the merchant's own price, fills the image/category/unit, and saves only when the manager submits the form. Existing products are never automatically filled by a scan.

The authenticated supermarket ready-made catalog uses separate source tables. It loads 48 products per request, supports section/name/candidate-code search and the existing camera scanner. The original food catalog route and data are preserved. A source item is copied only on a manager's explicit request, with their selling price. Products start hidden unless publish is selected. Repeated imports use deterministic tenant/source IDs and retain existing prices, categories and visibility. No merchant barcodes are assigned from unverified candidate codes.

Input: 21,342 products and 21,342 product/image associations from the supplied image manifest (21,330 manifest entries). Original provenance remains in the prepared archive; imported source evidence retains retailer identifiers and references. 2,190 source-flagged products remain pending. The other 19,152 have usable name/category data; barcode evidence remains unverified independently. Image rights remain pending and these images are not exposed or copied until approved. This release does not claim visual rights review of 21,330 images.

Restoring the 355 original products into a temporary table reproduced the snapshot checksum. No public customer tables were replaced or reseeded. Enabling the catalog permission for the two existing supermarket businesses is the only intended tenant configuration change; all other existing modules, products, prices and links are retained.

Validation: TypeScript/production build and PGlite supermarket import tests cover manager/tenant access, pending sources, draft creation, price validation, unreviewed image exclusion, no automatic barcode assignment and repeat imports preserving the merchant price. A live transaction can validate the import and roll back without persisting a merchant product. Production data fingerprints are compared to the snapshot after source ingestion.
